# Naslukh ASR (Android)

Маленькое приложение только для проверки `@naslukh/speech-rn`: запись / файл → офлайн GigaAM → текст.

Кнопка **Фраза** запускает `listenOnce()`: скажите фразу и замолчите — Silero VAD сам завершит захват, затем GigaAM вернёт текст. **Завершить** распознаёт уже захваченную речь, **Отмена** прекращает прослушивание без результата. Ручная запись и распознавание файла доступны отдельно.

В настройках длительность тишины перед завершением **Фразы** регулируется отдельно (по умолчанию 1,0 с); пауза для сегментов аудиофайла остаётся 0,25 с.

Для **Фразы** порог VAD по умолчанию 0,5 (для файла — 0,15). Говорите после сообщения «Слушаем…»: кнопка сначала подготавливает микрофон. Захваченный звук доступен по кнопке **Слушать** после распознавания.

После распознавания **Фразы** на экране показаны замеры в миллисекундах. Те же нативные замеры пишутся в Logcat с тегом `NaslukhTiming`; время от кнопки до «Слушаем…» логируется отдельно из приложения. Интервалы VAD включают ожидание речи и саму фразу. Время от остановки записи до текста заканчивается на результате GigaAM, до JS-corrector и обновления экрана.

В debug-сборке для диагностики пропущенного начала фразы кнопка **Слушать вход** воспроизводит первые секунды микрофона до срабатывания VAD. Файл `naslukh-pre-vad.wav` хранится только в кэше приложения и удаляется перед следующим прослушиванием; в release-сборке диагностическая запись и кнопка отключены. Уровень сигнала в debug пишется в Logcat с тегом `NaslukhInput`. Кнопка **Слушать** использует отдельный WAV фразы, сохранённый по явной опции `saveAudio: true`.

## Проверка Android MVP на OnePlus 7 Pro

20 последовательных вызовов `listenOnce()` с повторяемой записью через микрофон завершились автоматически без зависаний и перезапуска процесса. Первый вызов создал GigaAM за 1213 мс; следующие 19 переиспользовали recognizer без повторной загрузки. Задержка от остановки записи до текста для повторных вызовов: 371–425 мс, медиана 406 мс.

RAM приложения (PSS): 143 МиБ до загрузки GigaAM, 432 МиБ после первого вызова, пик 453 МиБ к 20-му, 446 МиБ после простоя. После перезагрузки React-модуля в том же процессе PSS снизился с 468 до 197 МиБ; следующий вызов заново создал recognizer. После серии проверены `cancelListenOnce()` и `stopListenOnce()` посреди фразы; `stop` вернул распознанный текст.
